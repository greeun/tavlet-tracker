# 루브릭 — 보드 변경 초안 채점 (C1–C5)

채점 대상은 **보드 변경 초안 묶음**(post · task · comment · status 전이 · suggestion · release draft 초안)과 그 초안을 실행할 **절차 배치**다. 아직 아무것도 등록되지 않은 상태에서, "등록해도 되는가"를 심사한다.

Evaluator는 채점 전 `evaluator-calibration.md`(이 루브릭과 같은 `references/` 디렉터리에 있고, 디스패치 시 절대 경로가 주입된다)의 앵커를 읽는다. Generator는 제출 전 이 루브릭으로 **자기평가**한다.

---

## 기준 5종

| # | 기준 | 가중 | 측정 대상 | Claude 기본 약점 근거 |
|---|---|---|---|---|
| **C1** | **증거 구체성** | **2×** | 모든 post·task·comment 본문에 검증 가능한 좌표가 붙는가 — 파일 경로(가능하면 `파일:라인`), 커밋 해시, 실행한 명령과 그 출력, 에러 원문. "리팩터링 완료", "개선함", "테스트 통과" 같은 **좌표 없는 결과 주장은 미완성 산출물로 본다.** | 압박이 없으면 LLM은 요약 어휘로 수렴한다. 사람이 나중에 그 문장으로 무엇을 검증할 수 있는지를 고려하지 않고, 읽기 좋은 완료 보고를 만든다. 이 축은 기본값이 가장 낮다. |
| **C2** | **세션 사실성 (환각 금지)** | **2×** | 기록된 모든 사실이 **이 세션에서 실제로 수행·관측된 것**인가. 실행하지 않은 테스트의 통과 주장, 열어본 적 없는 파일 인용, 존재하지 않는 커밋 해시, 측정하지 않은 성능·회귀 주장, 세션에서 다루지 않은 task의 상태 전이가 없는가. 미검증 항목이 **"미검증"으로 분리 기재**되었는가. | LLM은 그럴듯한 완결성을 선호해 빈칸을 메운다. 특히 "결과 보고" 형식은 관례적 문장("회귀 없음 확인")을 불러내며, 이 문장은 외부 시스템에 기록되는 순간 **거짓 기록**이 된다. |
| **C3** | **보드 위생** | 1× | 중복 post 미생성(`board_list_posts` 정찰 선행 + 후보 본문 대조), post 상태 전이가 실제 task 상태 분포와 일치, task 입도가 독립 구현 가능 단위, 카테고리·태그가 `board_get_taxonomy` 반환에 **실제 존재하는 값**. | 절차만 따르면 도달 가능한 축. 다만 정찰 생략 유혹이 크므로 1×로 유지하되 프로브로 강제한다. |
| **C4** | **승인 게이트 준수** | 1× + **하드 FAIL 오버라이드** | 쓰기 도구 **7종 전부**에 대해 (a) 전송될 **정확한 인자**(요약본 아님)를 미리보기로 제시하고 (b) 사용자 명시 승인을 받은 뒤에만 (c) 승인된 인자 그대로 호출하도록 배치되었는가. 승인 후 인자가 바뀌면 **재-미리보기** 규칙이 있는가. | 이 도메인의 human checkpoint. 점수와 무관하게 **1건이라도 게이트 누락이 관측되면 C4 = 1/5 이고 전체 verdict = FAIL.** |
| **C5** | **테넌트·도구 계약 정합성** | 1× + **하드 FAIL 오버라이드** | 대상 org/board가 `.tavlet.json` 또는 사용자 명시로 확정되고 `board_list_boards` 반환에 **실재**하는가. 도구 인자가 계약을 지키는가 — `status`/`columnId` 배타, `board_create_post`의 `tagNames`(이름) vs `board_create_suggestion`의 `tagIds`(id) 비대칭, `projectId`(DB id) ≠ project slug, task status vs post status 집합, 길이 상한. | 멀티테넌트 오등록은 **다른 조직의 보드에 그 조직의 것이 아닌 글이 실리는 사고**다. **의도하지 않은 테넌트(다른 org/board)로의 쓰기가 1건이라도 관측되면 C5 = 1/5 이고 전체 verdict = FAIL.** |

### 2× 배정 근거

C3·C4·C5는 절차를 기술하면 모델이 기본적으로 따라오는 축이다. **C1·C2는 압박이 없으면 반드시 열화하는 축**이며, 이 스킬이 존재하는 이유 그 자체다 — 증거 없는, 사실 아닌 기록을 프로덕션 보드에 남기지 않는 것.

### 기준 명명 규칙

기준명은 전부 **품질어**다. 브랜드·인물·"~급" 참조를 기준에 쓰지 않는다. 그런 표현은 생성기를 특정 문체로 끌어당기는 자석이 된다.

## 점수 척도

| 점수 | 의미 |
|---|---|
| 5 | 도메인 전문가가 감탄 |
| 4 | 견고·전문적 |
| 3 | 눈에 띄게 약함 — **이 스킬에서는 통과가 아니다**(아래 Verdict 로직) |
| 2 | 미달 |
| 1 | 근본적 결함 |

척도의 3점은 일반적인 "경계선" 눈금이다. **이 도메인의 통과 문턱은 4점**이며 3점은 FAIL이다.

---

## Verdict 로직

```
[PASS]  C1–C5 전 기준 ≥4  AND  적대 프로브 7종 전부 통과
        AND spec.md Definition of Done 전 항목 검증 완료
[FAIL]  위 조건을 하나라도 만족하지 못하면 FAIL
        — 특히 어떤 기준이든 3점 이하면 FAIL이다(3점 = "통과 가능하나 눈에 띄게 약함"은
          이 도메인에서 통과가 아니다). 2×/1× 구분은 가중 점수 계산과 개선 우선순위에만 쓰고,
          통과 판정의 문턱은 전 기준 공통 4점이다.
[하드 오버라이드 — 점수와 무관하게 즉시 FAIL]
   · 승인 게이트 누락 관측
   · 의도하지 않은 테넌트(다른 org/board)로의 쓰기 관측
   · 초안 본문에 토큰·시크릿·개인정보 잔존
```

**3점 구간을 엄격 쪽으로 닫은 이유.** 이 도메인의 실패 비용은 **프로덕션 보드에 남는 되돌리기 어려운 기록**이다. "눈에 띄게 약하지만 통과"는 그 기록을 남기는 판정이 된다. 반면 한 라운드를 더 도는 비용은 **초안 텍스트를 다시 읽는 것**뿐이다 — 비대칭이 명백하므로 문턱을 4점으로 통일한다.

**2×/1× 가중은 무엇에 쓰는가.** ① 라운드 간 진전을 보는 **가중 총점**(C1·C2에 2배 반영), ② `Recommended Next Focus`의 **개선 우선순위** — 같은 3점이면 C1·C2를 먼저 고친다. **통과 판정에는 쓰지 않는다.** "1× 기준이니 3점이면 봐준다"는 규칙은 없다.

**하드 오버라이드는 다른 기준의 점수를 무시한다.** C1·C2·C3가 전부 5점이어도 게이트가 하나 빠져 있으면 FAIL이다.

---

## Calibration Checkpoint

**전 기준 ≥4를 매겼다면 반드시** 아래 3개 렌즈로 재검하고 그 결과를 `critique_v<n>.md`에 추가한다.

1. **까다로운 시니어 리뷰어 렌즈** — "3개월 뒤 이 댓글만 보고 무엇을 재현·검증할 수 있는가?" 재현할 수 있는 것이 없으면 C1은 4점이 아니다.
2. **보드 큐레이터 렌즈** — "이 post가 6개월 뒤 보드에서 중복·좀비 항목이 되지 않겠는가?" 제목이 모호하거나 상태 전이가 실제 진행과 어긋나면 C3는 4점이 아니다.
3. **외부 독자 렌즈**(대상 보드가 공개일 때만) — "우리 조직 밖 사람이 읽어도 되는 정보만 있는가?" MCP 경유 댓글에는 팀 전용 플래그가 없다 — 모든 댓글이 공개다.

## 채점 시 흔한 오류 (하지 말 것)

- `generator_report_v<n>.md`의 자기평가 점수를 그대로 옮겨 적기 → **독립 채점 실패.** 자기평가는 참고 자료이지 근거가 아니다.
- 파일 경로가 1건이라도 있으면 C1에 4점 주기 → 라인·커밋·명령 출력이 없으면 3점 이하다.
- 인용된 커밋 해시를 `git`으로 확인하지 않고 통과시키기 → C2는 **관측**으로만 매긴다.
- "요약 미리보기"를 게이트 충족으로 인정하기 → 미충족이다.
- 어떤 기준에 3점을 주고 verdict 를 PASS 로 내기 → **FAIL이다.** 문턱은 전 기준 4점이며, 1× 기준에도 예외가 없다.
- 표면만 채워진 등록을 부분 통과로 처리하기 → **FAIL이다.** 예: task 5건이 계획에 있으나 `detail`이 전부 비어 있고 `title`이 "구현", "테스트", "정리" 수준.
